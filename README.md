# Discord 文件仓库 Bot（Repo Bot）

一个以 **Discord 本身作为存储后端** 的文件仓库机器人：成员可以上传任意类型的文件，
所有文件统一归档到 **当前服务器的专用子区** 或 **独立存储服务器**（由管理员设置），
并且内置 **下载审计机制** —— 每一次下载都会记录「谁、在什么时间、下载了哪个文件」。

## ✨ 功能特性

- 📤 **任意文件上传**：通过 `/upload` 上传任何附件，自动生成唯一文件 ID；
  `/upload_batch` 一次最多批量上传 10 个文件（可统一设置密码与声明）
- 📚 **作者合集**：`/collection` 一键开启个人合集面板——面板按「受保护/普通」
  分组列出你的全部文件，任何人下拉选择即可下载；**开启合集后你的文件退出仓库
  编号池**（不占 # 编号、不出现在 `/files` 与 `/search`），经合集渠道专属分发，
  关闭合集后按原上传顺序自动重新编号回列；成员执行 `/collections` 可浏览
  所有开启了合集的作者，选择作者即可直接下载其合集文件；上传/删除文件后面板自动刷新
- 📜 **首次使用需同意条款**：成员第一次使用 Bot 时会弹出服务条款与隐私政策，
  点击「同意并继续」才能正常使用（`/terms` 可随时查看；条款全文链接可在 .env 配置）
- 🔍 **发布审核（可选）**：`/review_config` 开启并设置审核频道后，所有上传
  先进入待审核状态（不出现在列表/搜索/下载中），审核工单（含文件附件与声明）
  发送到审核频道，管理员「通过」自动发布、「拒绝」移除文件，结果私信通知上传者；
  关闭审核则所有上传直接发布
- 👑 **管理员豁免可配置**：服务器所有者通过 `/exempt_config` 设置「发布审核」
  「下载风控」是否对管理员生效（默认：审核对管理员生效、风控对管理员豁免）
- 📝 **声明**：上传时可附加一段作者声明/免责声明（弹窗输入，最长 1000 字），
  随入库卡片、`/fileinfo` 与审核工单展示
- 🗂️ **两种存储模式**（管理员通过 `/storage_mode` 切换）：
  - **子区模式（category）**：自动在当前服务器创建 `📁 文件仓库` 分类 + 存储频道，
    也可以通过 `category` 参数**直接使用你已建好的子区**；
    存储子区与频道自动设为**私密**（@everyone 不可见，仅 Bot 可用）
  - **独立服务器模式（guild）**：将文件存储到另一个专门的 Discord 服务器
- 🔢 **文件编号**：每个文件自动分配服务器内编号（#1、#2……），
  `/download`、`/fileinfo`、`/history`、`/delete` 均可直接输入编号操作；
  开启合集的作者的文件不占编号，经合集渠道分发
- 🖱️ **点选即下载**：`/files`、`/search` 结果页自带下拉菜单，选中文件直接
  进入下载流程（加密文件自动弹密码窗），无需记编号敲指令；`/files` 支持翻页
- ⌨️ **编号自动补全**：`/download`、`/fav`、`/fileinfo` 等指令输入编号时自动
  弹出文件候选，边打字边模糊过滤，不用记编号
- 🖼️ **展示频道卡片**（可选）：管理员 `/showcase_channel` 设置后，新发布的文件
  自动在展示频道发卡片，卡片上直接点「📥 下载」「⭐ 收藏」——刷到即下
- 📦 **直发文件**：验证通过后文件直接发到聊天（仅你可见），超过 Bot 发送上限
  的文件自动回退为下载链接；成功消息附带「再次下载」按钮
- ⭐ **收藏夹**：`/fav` 收藏常用文件（或在 `/files` 收藏菜单里点选），
  `/favs` 打开收藏清单一键下载
- 🕘 **下载历史**：`/mydownloads` 查看自己最近下载过的文件，可快速重下
- 🗳️ **一键整理**：`/organize` 预扫描后发起管理员投票（范围可选当前频道 / 当前子区 /
  整个服务器，默认需 1 / 2 / 3 名管理员同意，可用 `/vote_config` 调整，发起者自动计 1 票），
  自动迁移旧位置文件，并**扫描范围内频道里未登记的散落文件**（成员直接发的），登记入库后归拢到存储频道；
  **投票通过后进入范围确认面板**：选择「黑名单（整理所选以外）/ 白名单（只整理所选）」
  模式 + 名单频道，可开关「散落文件登记」（关闭后仅迁移已登记文件），
  还可一键保存为默认配置；执行中可用 `/organize_cancel` 强制取消
- ⛔ **下载风控**：`/risk_config` 配置「时间窗口内下载次数上限 + 封禁时长」，
  触发成员在封禁期内无法使用 Bot 任何指令（到期自动解封，管理员不受限）；
  **触发后处置方式可选**：`自动封禁` 立即限制，或 `通知管理员处理`——发送待处理工单
  并 @管理员角色（工单频道优先，未设置则退回管理/审计日志频道），管理员可一键
  「立即封禁 / 放行」，**超过设置的处理时限仍未处理则自动封禁**；
  工单按钮重启后自动恢复，超时扫描持续运行，不会因 Bot 重启而漏处理
- 🚫 **管理员手动禁用**：`/ban_user` 直接禁用成员使用 Bot 的全部指令
  （可设时长，不填则永久），`/unban_user` 随时解除；禁用/解除均私信通知本人
  并写入管理日志，待处理风控工单会一并关闭避免重复处置
- 🎫 **申诉工单**：被风控成员 `/appeal` 提交申诉，Bot 发送到 `/ticket_channel`
  指定的频道并自动 @所有管理员角色，集齐足够管理员同意方可解封（默认 2 票，可用
  `/vote_config` 调整；同票数拒绝则驳回）；
  工单按钮重启后自动恢复，不会因 Bot 重启而卡死
- 🗳️ **投票人数可配置**：`/vote_config` 统一调整各类管理员投票所需同意人数
  （一键整理·频道 / 一键整理·子区 / 一键整理·全服 / 初始化服务器 / 申诉工单，范围 1~20，仅本服务器生效）
- 🔒 **下载密码**：上传时可选择设置密码（弹窗输入），下载该文件需输入正确密码，
  密码错误会记入管理日志
- ✏️ **上传重命名**：上传准备页可直接修改入库文件名（自动保留扩展名），
  改名记录同步到管理日志
- 🛡️ **管理日志**：`/storage_mode`、`/log_channel`、`/organize`、`/delete` 等
  管理员操作自动记录，可用 `/admin_log_channel` 单独设置管理日志频道
  （未设置时跟随审计日志频道）
- 🕵️ **下载审计**：下载必须经过 Bot 代理（`/download`），每次下载落库记录
  用户 ID、用户名、时间戳，并累计下载次数
- 📊 **审计能力**：管理员可查看任意文件的下载历史、任意成员的下载记录
- 🔍 **检索**：文件列表分页浏览、按名称/描述搜索
- 🗑️ **权限可控**：仅上传者或管理员可删除文件、查看下载历史
- 📝 **审计日志频道**：上传/下载事件自动推送到指定频道

## 🚀 部署

### 1. 创建 Discord Bot

1. 前往 [Discord Developer Portal](https://discord.com/developers/applications) 创建应用
2. 在 **Bot** 页面复制 Token
3. 在 **OAuth2 → URL Generator** 勾选 `bot` 和 `applications.commands`，
   Bot 权限至少勾选：`Manage Channels`、`Send Messages`、`Attach Files`、`Read Message History`
4. 用生成的链接邀请 Bot 进服务器（若使用独立存储服务器模式，也要邀请进存储服务器）

### 2. 配置

```bash
git clone https://github.com/Hum404/discord-repo-bot.git
cd discord-repo-bot
cp .env.example .env
# 编辑 .env，填入 DISCORD_TOKEN
```

`.env` 配置项：

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `DISCORD_TOKEN` | ✅ | Bot Token |
| `STORAGE_GUILD_ID` | 独立服务器模式必填 | 存储服务器的 Guild ID |
| `DATABASE_PATH` | 否 | SQLite 数据库路径，默认 `data/repository.db` |
| `MAX_FILE_SIZE_MB` | 否 | 单文件大小上限（MB），默认 24 |
| `TOS_URL` | 否 | 服务条款全文链接（同意提示中展示） |
| `PRIVACY_URL` | 否 | 隐私政策全文链接（同意提示中展示） |


### 3. 运行

```bash
pip install -r requirements.txt
python run.py
```

Docker（可选）：

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "run.py"]
```

## 📄 日志查看

Bot 有三层日志，按用途选用：

1. **运行日志（排障用）**：启动信息、异常堆栈、整理失败明细等
   - 前台运行时直接输出在**终端控制台**
   - 同时写入文件 **`logs/bot.log`**（自动轮转：单文件 2MB，保留 5 份；
     可用环境变量 `LOG_DIR` 修改目录），启动时控制台会打印其完整路径
   - systemd 托管：`journalctl -u <服务名> -f`；Docker：`docker logs -f <容器名>`
2. **审计日志（服务器内）**：`/log_channel` 设置频道后，每次上传/下载实时推送
3. **管理日志（服务器内）**：`/admin_log_channel` 单独设置（未设置时跟随审计日志频道），
   记录 `/storage_mode`、`/organize`、`/vote_config`、`/delete`、风控处置等管理操作

## 🔍 下载审计说明

Discord 原生附件链接无法追踪访问者（且 CDN 链接会过期）。本 Bot 的做法是：

1. 上传时，文件被转存到 **Bot 控制的存储频道**，原始消息定位（频道 ID + 消息 ID）
   与元数据一起存入 SQLite
2. 下载时，用户必须通过 `/download <文件ID>` 向 Bot 索取，Bot 从存储频道取回文件并转发
3. 转发前先将 **文件 ID、用户 ID、用户名、服务器 ID、时间戳** 写入 `downloads` 表
4. 管理员/上传者可用 `/history` 和 `/audit_user` 随时审计；若配置了日志频道，
   每次上传/下载都会实时推送审计消息

> ⚠️ 注意：由于 Discord 平台限制，Bot 单文件发送上限受服务器加成等级影响
> （通常 25MB，加成等级 2 为 50MB，等级 3 为 100MB）。请按实际情况调整
> `MAX_FILE_SIZE_MB`。
